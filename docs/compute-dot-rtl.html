INT8 dot-product ジョブ RTL 試作

2026-10-23。rtl/compute/int8_dot_job.v は既存 int8_mac_lane と int8_requantize をそのまま接続し、1出力の dot-product を実行する wrapper。演算部品間の制御を検証するための試作で、DDR、tile scheduler、Conv、モデル実行、ホスト通信には未接続。

ジョブと状態遷移

  • IDLE の begin_valid/ready で bias、入力零点、出力scale符号化(multiplier/shift)、出力零点、clamp上下限、K(length)を一括検証して latch。以降、外部設定信号が変化しても進行中ジョブに影響しない。
  • START の1サイクルで MAC lane を bias 初期化。この時点では sample を受理しない。
  • STREAM で sample_valid/ready の成立した順に K 個の signed INT8 activation/weight を加算。差は activation-input_zero_point。無効サイクルは加算せず、K は受理した sample だけを数える。
  • 最後の sample 後に FINISH で MAC を終了し、QUANT で累積結果を requantizer に渡す。K=0 は STREAM を通らず bias を再量子化する。
  • OUTPUT で signed INT8 の result_valid/result を保持。result_ready で消費して IDLE に戻る。結果消費と新 begin の同時受理はしない。

begin直後、sample は最短でも次の START クロック後から受理可能。最後のsample後、FINISH・QUANTの2クロックを経て result_valid が立つ。K=0 の場合は begin→START→FINISH→QUANT の順に進む。begin/sample/result の各 valid ソースは ready までpayloadを保持する。フェーズ外のbegin/sampleは受け付けず、副作用もない。Kより多い sample は次のジョブの一部にはならない。K不足の場合はSTREAMで待機し、自動終了やtimeoutはしない。

設定・エラー・reset

accumulator biasはsigned INT32、入力零点は-128..127、multiplierは0..2147483647、shiftは0..62、出力零点/clampは-128..127かつlower<=upper。Kはunsigned32bitの0..4294967295。Kにメモリ上の制約はなく、将来のコマンド受付側が実バッファ長と照合する。

設定ポートは不正値検出のため一部広い型を使うが、ポート幅外の値をpack前に切り捨ててはならない。Kは負値を表現できないため、受付側で負値を拒否する。ReLUはcallerがlower=max(-128,output_zero_point)を設定する。

error_codeは0=正常、1=INVALID_CONFIG、2=ACC_OVERFLOW。受理したbeginの設定が不正ならMACを開始せずFAULTへ進み、以前のresultを変えない。MAC各加算でoverflowした場合は既存laneのerrorが立ち、外部errorも同サイクルから有効になる。直前の正常な累積値を保ち、成功結果を公開しない。コントローラは次クロックでFAULT状態に収束する。FAULT中はbegin/sample/resultのready/validを停止し、resetまで回復しない。

同期active-high resetは最優先で、途中ジョブ、未消費出力、error、内部設定を破棄し、両部品も同時resetする。reset後のresultは0。通常の複数ジョブ間にresetは不要で、結果消費後に次ジョブを開始する。busyはIDLE以外で1となり、FAULT中も1。errorが1の時はbusy終了を待たずresetで回復する。使用前に最低1クロックのresetが必須。

CPU goldenによるジョブ単位の結果とcycle状態oracleを生成し、全入出力を検査する自己検査Verilog TBを出力する。K=0、符号端値、ゼロmultiplier、ReLU、late overflowの両方向、不正設定8種、入力bubble、余分sample、出力backpressure、設定latch、複数ジョブ、START/STREAM/FINISH/QUANT/OUTPUT各段階のreset abortを含む。

TBを動かす場合はwrapperと既存MAC/requantの3 RTLファイルをまとめてcompileする。ここで成功したホストテストはVerilogを実行していない。RTL simulation、合成、タイミング、資源使用量、実機動作は未検証。新規シミュレータ導入、Tab5/USB/COM操作、性能向上の主張は行っていない。
