GPU LAB 実機評価（2026-10-22）

Tab5 / ESP32-P4 Rev 1.3 / 400MHz / COM22、ESP-IDF 5.5.5、BSP 1.3.2、LVGL 9.6.0~1。

640×360 RGB565、CPUモード。24フレームをウォームアップし、続く120フレームを採用した。

FPSは描画からソフトウェア表示処理までの値で、LCDの走査FPSではない。

USBから約1秒ごとに状態を取得。単一実行の値で、反復測定のばらつき評価はまだ行っていない。

現在の書き込み済みビルド

ELF SHA256: 59b4947204b3fce59b1975040983294eab96c93f7771638a2096e2727a75fffd

LVGLのメモリ管理はESP-IDF標準malloc/free。固定64KB領域への制限を外している。

画像プレビューから文字欠けを疑ったが、保存画像の拡大切り出しと画素照合では文字は正常だった。

実際のパネルでの文字欠けは確認していない。

途中で試した手動メモリ拡張では起動停止が起きたため撤去し、起動・API応答を復旧した。

現在のビルドで以下の実機テストを再実行している。

USB・画像・描画の検証

  • info/status/results、設定変更、測定開始・進捗取得、一時停止を確認。
  • 不正JSON、長すぎる要求、未知コマンド、無効引数、未対応FPGAを拒否。
  • 無効な設定要求で既存設定が変わらないことを確認。
  • 測定中の重複測定・画像取得をbusyで拒否。
  • 8シーンの完成画像を取得し、長さとFNV-1aを照合。
  • 測定後のLIGHT画面とMEDIUMの流れ画面で、それぞれUI全体を3回撮影。
  • 各3回の停止中画像は全体のチェックサムが一致。取得画像の文字・グラフ・ボタンを目視確認。
  • タイトル領域は以前の正常な画像と画素単位で一致。今回の検証では文字欠けを再現していない。
  • ホストで8シーン×3負荷、再現性、アニメーション変化、深度、境界、測定集計を検証。
  • 流れの連続フレーム計算とフレーム0からの再生が同じ結果になることを検証。
  • ESP32-P4向け全体ビルド、実機書き込み、Flashのハッシュ照合に成功。

UI画像は実機内部のLVGLによる生成画像であり、液晶の実写や物理走査の読み出しではない。

バックライト点灯やパネルの実表示は、API画像だけでは確認できない。

Tab5全体のエミュレータは使用していない。

流れの3負荷

生データと再実行

ビルド情報・JSON/CSV結果・代表UI画像は 評価データ に保存。

全取得画像と作業時のデータは build/hardware-validated/。

ログは build/hardware-validated.log と build/flow-validated.log。

buildフォルダはGit管理外のローカル生成物。


python tests/hardware_usb.py --port COM22 --bench-all-light --output build/hardware-validated

python tools/gpu_lab.py --port COM22 suite --wait --timeout 3600 --output build/cpu-suite.json

最初のコマンドは設定・画像・LIGHT条件の検証で、全24条件の一括測定ではない。

全24条件の実機測定、反復測定のばらつき、LCD同期・ティアリング、GPU接続後の比較は今後の作業。

GPUの実測値はまだない。フラクタル・炎の全画素演算はCPUで重く、GPU比較の候補になる。

最終状態はFlow / cylinder wake、MEDIUM、CPU、アニメーション実行へ戻した。
