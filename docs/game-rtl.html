部品の範囲

rtl/game/triangle_coverage.v は reference/game_gpu_reference.py の

G0三角形規則に合わせ、1候補画素の画素中心におけるcoverageと重みを計算する。

  • 頂点ax/ay/bx/by/cx/cy: signed 16bit、4fractional bits（raw -32768..32767）。
  • pixel_x: unsigned10bit、pixel_y: unsigned9bit。画素中心をraw (x*16+8,y*16+8)で評価する。
  • 実targetの640×360以内やscissor以内かどうかは呼出し元が判定する。部品は候補画素をclampしない。
  • area<0ではb/cを交換して正規化し、Y下向きのtop-left規則で境界を判定する。
  • area=0はdegenerate=1, covered=0, area=0, weights=0。
  • areaは非負。weight_a/b/cは入力の元の頂点順に対応する。内部b/c交換を外部で再実行しない。
  • 非退化の場合、画素が外側でも符号付き重みを返し、weight_a+weight_b+weight_c=areaを満たす。
  • winding_swappedは入力areaが負だったことを示す。

深度補間/除算、strict-greater深度比較、color、Z、scissor、bounding-box走査、

framebufferアクセス、DDR、命令受付は含まない。

後段はcovered=1のサンプルだけを使い、元のZ順のまま

floor((wa*za+wb*zb+wc*zc)/area)を別の正確な整数除算器で実行する必要がある。

この除算・比較を省略した部品をG0描画完成とは扱わない。

サイクル契約

clkの立上りでin_valid=1の入力を取り込み、その立上り後に登録出力とout_valid=1が現れる。

1段の登録出力、バックプレッシャーなし、毎クロックに候補1個を渡せる論理インターフェース。

実際に達成するクロック周波数/毎秒サンプル数を保証するものではない。

in_valid=0を取り込んだクロックはout_valid=0、データ出力は前値を保持する。

reset_n=0は非同期にout_validと全出力を0にする。

受信側はout_validが立つサンプルだけを採用する。

幅と符号の監査

頂点を64bitへ符号拡張してから差分・積を計算する。16bitのまま頂点差を引かない。

pixelはゼロ拡張した64bit符号付き値からシフト/加算する。

edge関数の各引数、差分、一時変数、戻り値はsigned64bitで統一。

頂点の最大差65535、画素中心もraw16bit範囲内なので、保守的に

|edge| <= 2*65535*65535 < 2^33。signed64bitでarea/重み/符号反転を扱える。

Verilogでの64bit積は最終edgeの有効範囲内で切捨てが発生しない入力契約とする。

この初版は幅の明示を優先しており、合成時のDSP/LUT量や乗算器の縮約結果は未確認。

深度重み積と総和の幅は、後段実装時に別途保証する。

PC上の期待値とRTLテスト準備

tests/rtl_game/generate_vectors.py が既存参照の edge/inclusive を利用して

3,328組の入力/期待値を生成する。頂点境界、最大値、負座標、退化、水平/垂直境界、

画素中心上の辺、両巻き順、共有対角線と固定seed乱数2,048組を含む。

inputs.mem/expected.memはVerilogから同じ値を読める形式。manifestに件数とSHA256を記録する。
