Tab5 FPGA ゲーム GPU と WholeBody 推論アクセラレータの開発計画

更新日：2026-10-22。用途別の2設計を採用する方針は合意済み。詳細ABI・数値形式はv0.1設計案として検証する。

目的と構成

同じTab5とTang Primer 20Kを使い、ゲーム用GPUとCNN推論用アクセラレータを別ビットストリームで開発する。

ゲームでは同じポリゴンゲームをCPU/GPUで比較し、推論ではPINTOさんのWholeBodyモデルを同条件で比較する。

共通化するのは通信、DDR3アクセスの下位層、バッファ記述子、完了通知、エラー、測定記録。

初期段階で両回路を同時搭載・同時実行しない。ビットストリームの切替はFPGA再構成で、VRAMやモデルの保持は保証しない。


flowchart LR

  T[Tab5 ゲームまたは推論アプリ] --> H[共通ホストドライバ]

  H <--> L[8bit 接続とコマンド受付]

  L --> G[ゲーム用ビットストリーム]

  L --> C[推論用ビットストリーム]

  G <--> D[共通仕様の DDR3 とバッファ管理]

  C <--> D

図の2経路は用途ごとに再構成して選ぶ。Tab5側のCPU基準実装とUSB評価APIは継続利用する。

2026-10-22の指示により、ユーザーの再開指示までTab5の書き込み・USB操作・読み取りを行わない。

その間は設計、ホスト参照、モデル解析、RTLシミュレーション、ビルドまで進める。

成功の判定

ゲームは同じ解像度、同じシーン、描画機能、入力リプレイで比較する。

目標は640×360 RGB565で30フレーム処理FPSを維持できるシーン規模の拡大。

描画単独、転送、表示、ゲーム全体の時間を分け、頂点をCPU処理する段階などの分担も表示する。

推論はモデル・重み・処理解像度・量子化・前後処理・閾値・入力列を固定する。

FPGA区間が速いことと、入力から結果表示までのFPSが上がることを別々に判定する。

比較先は同じグラフを動かすP4のCPU実装。別のYOLOモデルの公表値やPC速度をP4基準値に流用しない。

検出の品質を保てない速度向上を成功と扱わない。未達の場合もボトルネックを測定結果として残す。

設計を固定する順番

  • バッファの所有権、コマンドの粒度、数値形式、演算子の意味、エラー、完了条件を決める。
  • PC上の参照実装と境界値テストを作り、GPU用・推論用の正解を固定する。
  • RTLを参照結果に照合し、合成後のLUT・DSP・BRAM・タイミングを記録する。
  • 到着した基板の配線を照合し、低速疎通からDDR3とDMAへ進む。
  • アプリ全体のCPU/FPGA比較へ進む。未対応命令は明示的に拒否し、暗黙にCPUへ逃がさない。

命令はアプリ側のジョブ指示と内部ALU演算を分ける。命令番号の割当だけを先に固定しない。

ゲームの詳細はゲームGPU仕様、推論は計算アクセラレータ仕様で扱う。

共通契約の案

ホストはHELLO/CAPSで用途、ABI、ビルドID、対応演算と制約を取得する。

UPLOAD/DOWNLOAD、バッファ定義・破棄、SUBMIT、FENCE/STATUS、COUNTERSを共通概念とする。

ジョブは連番とセッション/構成IDを持ち、DDR3の領域ID＋オフセット＋長さを使う。

アドレスの桁あふれ、越境、重複領域の扱い、アラインメントを検証してから実行する。

キュー内はまず逐次実行。成功したFENCEまでCPUは入力バッファを書き換えず、出力を使用しない。

タイムアウト時は「完了」と扱わず、再同期と状態照合を行う。再送してよい命令と二重実行禁止の命令を分ける。

物理フレーム形式、CRC、バス方向、READYの意味は接続試験で定義する試験用プロトコルと

本番ジョブABIを分離して設計する。エラーで停止した際のバス解放を最優先する。

演算子とABIが確定するまでは、バージョンを付けて互換性を主張しない。

キャリア仕様の確認結果

参照したキャリアは 0ff1502e6d2f10f1681480de09087fb3953f39ed の共通仕様。

D0〜D7はGPIO18/19/5/3/4/2/48/47、CLK16、READY45、DIR51という暫定案。

FPGAパッケージピン、I/Oバンク電圧、GPIO競合、方向切替、電源条件が確定していない。

この状態では最終CST・基板用ビットストリームを確定できない。配線を推測して出力しない。

GPU要件は 256e4c1、Linux側の要求確認時の版は 519c09515f79704f4b9f3e679d622f87ab2a56e5、

外部メモリ研究側は e4aa69d09b2643d6f62fe686ef0f3284b109c541。

Linux側のFPGA通信は計画段階として扱い、Linux用とGPU用の同時動作を要求しない。

キャリア側の作業中ファイルや共通配線仕様は、この作業から変更しない。

現在までの結果

CPU版GPU LAB、USB評価API、8シーンのLIGHT実測と流れの3負荷は既存評価に保存済み。

FPGAによる描画・推論の高速化結果はまだない。

N版Wholebody25の実ファイルを解析し、ConvだけでなくSigmoid/Mul、Pool、Resize、Softmax、レイアウト処理が必要と確認した。

推論モデルの選定と解析結果はWholeBodyモデル評価を参照する。

整数三角形ラスタライズとINT8 GEMM/ConvのPC参照実装、境界値テストを追加済み。接続試験用Tab5ファームはビルド成功、FPGA疎通RTLとテストベンチは作成済みです。RTLシミュレーション、合成、実基板top/ピン制約、bitstreamは未完了であり、M2の完了条件はまだ満たしていません。
