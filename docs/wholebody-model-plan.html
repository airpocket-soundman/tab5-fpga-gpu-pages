PINTO WholeBody モデルの選定と評価

更新日：2026-10-22。Nを初期解析対象とし、Nが事前に定めた検出品質基準を満たさない場合はT/Sを評価する。

モデルの規模と処理解像度は別の変数として比較する。最小モデルを最終採用する決定ではない。

対象と出力

候補はPINTO0309のYOLOv9 Wholebody25。

身体、頭、顔、手足、方向、属性など25クラスの物体検出で、133点の姿勢キーポイントモデルではない。

先に調べた一般的なYOLO11の結果や姿勢推定の指標を、このモデルの結果として使わない。

配布元READMEによると、post版は前処理とNMS等の後処理を含む。

ファイル名の解像度と外部入力画像の寸法の意味は版により異なるため、実グラフの入出力を検査する。

ユーザーの指定が別のWholeBody世代を意味する場合も、同じ監査手順で差し替えられる構成にする。

実ファイルの解析結果

配布元フォルダの確認版：17cef79f2fe593a3c8f8e92d5970b0ca26e52063。

download_n.shの公開アーカイブからONNXを選択し、ONNX checkerとshape inferenceを実行した。

配布スクリプトは実行せず、モデルを読み出した。モデルのSHA256は各JSONに記録している。

N版入力出力初期化テンソルのバイト数畳み込みMAC数
raw 128×160FLOAT 1×3×128×160FLOAT 1×29×4202,419,06461,063,640
raw 192×320FLOAT 1×3×192×320FLOAT 1×29×12602,429,144183,190,920
post 128×160FLOAT 1×3×H×WFLOAT N×72,419,22861,063,640

raw出力の29は4座標と25クラスに対応する構成として、デモのdecode実装と照合して確定する。

MAC数はshapeが判明したConvのみで、活性化・前後処理・転送などの処理量を含まない。

初期化テンソルには学習済み重み以外の定数も含まれる。最大テンソルの大きさはピーク同時使用メモリではない。

raw版の演算子はConv 186個、Sigmoid 180個、Mul 180個、Add 44個と、

AveragePool/MaxPool/Resize/Concat/Slice/Split/Reshape/Transpose/Softmax/Sub/Div。

post版にはNonMaxSuppression、Gather/GatherND、Castなども含まれる。

したがってConvとReLUだけを作って「WholeBody対応」と扱うことはできない。

配布ファイルはFLOATグラフで、INT8量子化済みモデルを確認したわけではない。

Conv属性の追加監査では、3つのN版ともgroup=1が180個、group=4が6個。group=4はv0.1のgroup=1演算器の直接対象外です。入力・重み・出力のchannel領域を分割してgroup=1の複数ジョブへ変換する方法をPC参照で検証します。量子化、配置、ジョブ間の転送・結合費用は別途評価が必要です。各Convの形状、kernel、stride、dilation、pad、除外理由を解析JSONへ追加しました。

属性の意味はONNX Conv仕様に従います。監査上のgeometry candidateは形状契約の候補であり、RTLやINT8モデルの対応済み判定ではありません。

解析JSON：

  • N raw 128×160
  • N raw 192×320
  • N post 128×160

選定手順

  • 同じ入力列でNの128×160と192×320をPC参照実行し、顔・手などの見落としとボックスを確認する。
  • Nで検出が不足する場合、同じ処理解像度でT、次にSを監査・参照実行する。
  • 重みだけでなく特徴マップの生存期間、演算ワークスペース、P4/FPGA間の転送量を計算する。
  • INT8化の校正用入力と、別の評価用入力を分ける。スケール・ゼロ点・丸めをモデル成果物として固定する。
  • 品質基準を満たす候補から、P4 32MB PSRAMとFPGA 128MB DDR3へ配置可能な構成を選ぶ。
  • 同じ量子化モデルをCPU参照とFPGAで比較する。FP32からの品質低下も別途測る。

N/T/Sの実測比較はまだ行っていない。T/Sのモデルを監査済み・動作済みとは記録しない。

モデルがP4に収まらない場合、CPU基準をPC実行へ置き換えてP4比較と呼ばない。

タイル実行、外部保存、別の候補への変更を明示し、同じ実行条件の基準を用意する。

評価指標

  • PC FP32参照とのボックスIoU、クラス・スコア・検出数の差を、同じ閾値・NMS条件で比較する。
  • CPU整数参照とRTLの層出力を照合し、演算誤差とモデルの量子化誤差を分ける。
  • ラベル付き評価入力がある場合はクラス別の適合率・再現率やAPを測る。
  • 正解ラベルがない入力での参照モデルとの一致率を、真の検出精度やmAPと呼ばない。
  • 前処理、入力転送、FPGA計算、未対応CPU区間、出力転送、decode/NMS、描画を別々に測る。
  • 入力から検出表示までの遅延p50/p95、全体FPS、メモリ、転送量を保存する。

数値の合格閾値は評価入力を確認して決め、結果を見た後で条件を緩めない。

カメラ撮影と固定動画リプレイを分け、同じフレームを処理するリプレイを初期比較に使う。

Tab5を使用しない期間はPC参照・モデル監査・量子化とRTL照合までを対象にする。

再現とライセンス


python -m pip install onnx

python tools/onnx_audit.py path/to/model.onnx --output build/model-audit.json

モデルは配布元のdownload_n.sh等から取得する。重みはGitに追加しない。

Wholebody25フォルダはGPLv3の表示があり、

配布・改変・組込み時は対象ファイルのライセンスと帰属表示を確認する。

解析ツールの分割案は実装対応を示すものではなく、FPGAの性能見積もりも出さない。
