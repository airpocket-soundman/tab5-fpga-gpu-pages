三角形候補画素の coverage/depth 接続RTL

2026-10-23。rtl/game/triangle_fragment.vは既存のtriangle_coverage.vとtriangle_depth.vを接続する単一候補画素のwrapper。DDR、scissor、bounding-box走査、フレームバッファ書込み回路は含まない。CPU整数参照との出力比較用fixtureとTBを追加した段階であり、RTLシミュレーション・合成・資源/タイミング検証は未実施。

受理と出力

入力はraw signed12.4の3頂点XY、uint16の頂点Z/既存depth/color、候補pixel座標（X10bit、Y9bit）。受理はin_valid && in_readyの立上り。coverage側へ同時に座標を渡し、Z/old depth/color/pixel座標をlatchする。入力元はstall中validとpayloadを維持するのが通常の契約だが、wrapperは受理後に外部payloadが変わっても新しい入力を受け付けず結果に反映しない。

内部はIDLE→WAIT_COVERAGE→SEND_DEPTH→WAIT_DEPTH→HOLD_RESULT。未被覆/退化ならdepth dividerを起動せず、depth_pass=0/new_depth=0でskip結果を返す。coveredの場合はcoverageのarea/weightsを保持し、depthのreadyを待って投入する。coverage出力は元頂点順のweightsなのでZの順序を交換しない。最終結果にはcovered、degenerate、invalid_input、depth_pass、new_depthと元color/pixelを含む。

出力はout_valid && out_readyで消費し、stall中は全payloadを保持する。同時に次の入力を受理する最適化はせず、1候補のみin flight。write_enableは消費時だけのpulse条件で、out_valid && out_ready && covered && !degenerate && !invalid_input && depth_pass。深度不採用/skip/errorでは書込みを許可しない。実際の書込みは下流が担当する。

非同期active-low resetを両下位moduleと共有し、処理中/出力stall中のresetでは候補を破棄する。reset中はin_ready/out_valid/write_enable=0、解除後に古い結果を返さない。ピクセル座標のtarget範囲判定は外部責任で、640×360範囲外でもwrapper自体はcoverage候補として計算する。
