計算アクセラレータ仕様案 v0.1

2026-10-22。推論専用の別 FPGA bitstream として設計する。ゲーム GPU とは通信・DDR バッファ管理・ジョブ完了・性能計測を共通化する。現時点は演算規則と CPU 参照コードの提案であり、RTL 実装、資源使用量、速度、モデル精度を検証したものではない。学習・逆伝播は初期対象外。

評価対象とモデル選定

PINTO WholeBody25 の YOLOv9 N を最初の候補とする。モデル系列 N/T/S、入力解像度、FP32/INT8 は別軸として比較する。N の検出精度が用途に足りなければ上位サイズを検討する。採用判断にはモデルサイズ、検出品質、実行時間、メモリ使用量を用いる。

実 ONNX の監査では N 128×160 は FLOAT NCHW 入力 1×3×128×160、FLOAT 出力 1×29×420、重み初期値 2,419,064 bytes、Conv 186 個・61,063,640 MAC。25 class の部位・属性を含む box 検出であり、人体キーポイント出力ではない。配布モデルは FP32 で、INT8 化も精度評価も未実施。最大単一 tensor とピーク生存メモリを混同しない。

出典: PINTO model zoo 459_YOLOv9-Wholebody25。監査 JSON の hash と入力サイズで結果を同定する。

実行構造

ホストで ONNX を検査し、静的形状と演算属性を確定した実行計画を作る。モデル・定数・feature map は DDR に常駐させ、各 Conv のたびに Tab5 と往復しない。推論時は入力 upload、ジョブ投入、完了待ち、最終出力 download を基本とする。重み転送時間を含む cold start と常駐後の steady state を分ける。

命令共通ヘッダは共通 transport 仕様に従い、命令 payload は tensor descriptor ID、buffer handle + offset、形状、stride、dtype、量子化パラメータ handle、dependency/fence を使う。物理 DDR アドレスの自由指定は禁止し、範囲・重なり・配置・必要容量を投入前に検証する。v0.1 は連続配列のみ。実際の opcode 値と wire packing は共通仕様との統合時に固定する。

MAC エンジンは入力・重み tile を SRAM に読み、出力の INT32 partial sum を保持する。最初は 8×8 出力、K=16 を参照 tile とするが、並列 MAC 数・SRAM 配分は合成後に決める。Conv は完全な im2col を DDR に展開せず、入力 tile/halo を読みながら同じ MAC を使う。端数 tile をゼロ埋めし、出力境界外へ書かない。

数値規則

  • activation は符号付き INT8、tensor ごとに正の scale sx と零点 zx ∈ [-128,127]。実値は (qx-zx)*sx。
  • 重みは output channel ごとの正の sw[o]、零点 0 の対称 INT8。変換器は原則 [-127,127] を使う。ハードウェア演算自体は -128 も定義する。
  • bias は INT32、scale sx*sw[o]、零点 0。積 (qx-zx)*qw を INT32 bias に順次加算する。差は INT9 を必要とする。縮約順序は GEMM の K 昇順、Conv の入力 channel→kernel y→kernel x。
  • 毎加算で INT32 範囲を確認し、超過時 ACC_OVERFLOW。wrap やエラー通知を伴わない飽和処理は禁止。静的な最大値 bound も変換器で検査する。tile 間で再量子化しない。
  • 出力は clamp(round(acc*M[o]/2^shift[o]) + zy)。M は非負 INT31、shift は 0..62、積は INT64。丸めは最近接、ちょうど半分はゼロから遠ざける。負数の算術 shift だけで代用しない。
  • M/2^shift は sx*sw[o]/sy を近似した値。変換器が実 scale、符号化 scale、近似誤差を記録する。出力 clamp は通常 -128..127、融合 ReLU は下限 max(-128,zy)。
  • NaN/Inf、scale≤0、動的形状、未定義量子化属性はロード時に拒否する。

参照コードは compute_reference.py（開発リポジトリ内）。小さい行列・Conv に対する演算規則の検証用であり ONNX runtime ではない。

命令とサポート境界

命令v0.1 規則・段階
GEMM_I8A[M,K]×B[K,N]、bias[N]、INT32 出力。転置は別 layout 命令で明示。初期実装対象
CONV2D_I8NCHW/OIHW、group=1、stride/dilation/pad 明示。INT32 出力。初期実装対象
REQUANTchannel ごとの M/shift と出力零点、INT8 飽和。初期実装対象
ADD / MUL同形 tensor のみ。異なる scale は明示的 rescale、積は INT32 中間値から requant。broadcast は事前展開または明示 lower。後続対象

LAYOUTreshape は view、transpose/concat/slice/split は検証済み DDR copy。offset/stride を明示。後続対象
POOL / RESIZE / SOFTMAX対象 graph が必要とするため、実装するか CPU partition を明示する。最初から対応済み扱いにしない

CPU は画像 resize/letterbox、色変換・正規化、box decode、NMS を担当する。どの処理が配布 ONNX 内に含まれるかモデルごとに確認し、raw 出力モデルを優先する。grouped/depthwise Conv、FP32 MAC、任意プログラム実行は v0.1 対象外。

ロード時 capability に対して 全ノードと属性 を検査する。未対応ノードは UNSUPPORTED_OP と node 名・属性を返す。自動的に消す、未計算の値を返す、暗黙 CPU fallback は禁止。CPU fallback を許可する場合は実行計画に境界 tensor と FP32/INT8 の変換を明示し、境界ごとの転送量・実測時間を報告する。Conv のみの対応では本モデル全体を実行できない。

ベンチマークと合格条件

  • CPU golden と RTL simulation の小規模 GEMM/Conv/requant が bit exact。一致しない場合は性能評価へ進めない。
  • FP32 配布モデルと INT8 候補を同じ固定画像集合・前処理・閾値で比較。検出品質の採用基準はゲーム/カメラ用途の必要対象に合わせ、FPGA着手前に固定する。量子化 calibration と評価画像は分離する。
  • 同じ量子化モデルの CPU 実装と FPGA を比較し、量子化の効果とハードウェアの効果を分離する。Tab5 にモデルが収まるか・CPU 実行可能かも未検証。PC の CPU 数値を Tab5 baseline と呼ばない。
  • 初期化、前処理、upload、各演算・fallback、download、decode/NMS、表示、全体 wall time を分ける。median/p95、warmup/反復回数、model hash、入力サイズ、bitstream/build ID、ピーク DDR 使用量を保存する。
  • 単一 Conv の MAC/s は補助指標。入力画像から最終 box までの完了 FPS と latency が改善し、品質基準を満たして初めて YOLO 高速化達成とする。pipeline FPS と単画像 latency は別記する。

Tab5 は別プロジェクト利用中のため、書き込み・USB/COM 読取りを停止する。再開許可まで PC 参照検証、RTL simulation、graph lowering、合成評価に限定する。
