現在の用途別設計・実装順序は開発計画を正とします。ゲームGPUとCNN推論を別ビットストリームとして開発し、初期GPUはCPUで頂点処理、FPGAで画面座標三角形とZ処理を行います。以下の頂点変換・投影は後段の目標です。

目的

Tang Primer 20Kに描画処理を分担させ、ESP32-P4単体との描画時間、フレーム処理FPS、処理可能なシーン規模を同条件で比較する。FPGA利用時の性能差は実測で確認する。

共通ハードウェア

ESP32-P4 × Tang Primer 20K 共通ハードウェア仕様 を使用する。初期接続は8bit PARLIO、後に16bit化を検討。GPU用途にはLinuxは必須でなく、まずESP-IDFで実装する。

描画・転送の基本目標

  • 最初は640×360、RGB565、30FPSを目標とする。
  • 60FPSは追加評価の目標。実効転送帯域とP4側での拡大・表示速度を測定して判断。
  • 8bit×40MHzの理論帯域は40MB/s。
  • 640×360 RGB565の全フレーム転送量は460,800byte：30FPSで13.8MB/s、60FPSで27.6MB/s。
  • 1280×720 RGB565全フレームは1,843,200byte：30FPSで55.3MB/sとなり、8bit理論帯域を超える。
  • ダブルバッファと表示同期でティアリングを抑制する。実現可否はLCDドライバ実装に依存する。
  • 将来は圧縮・差分転送、16bit PARLIO等を検討する。

FPGA GPU機能（段階導入）

  • READ／WRITE／COPY／FILL、DDR3フレームバッファ
  • 画面クリア、2Dライン描画、矩形描画
  • 固定小数点の3D座標変換・透視投影・ワイヤーフレーム
  • 三角形塗りつぶし、Zバッファ、フラットシェーディング
  • 必要に応じてテクスチャマッピング、パーティクル、追加演算

評価シーンと測定項目

同じ回転キューブのシーンをP4単体（CPU Mode）とFPGA（GPU Mode）で描画し、オブジェクト数を増加させる。

  • 30FPSまたは60FPSを維持できる最大オブジェクト数
  • 頂点数／線分数／三角形数
  • 内部レンダリングFPSとLCD表示FPSを別々に測定
  • P4 CPU負荷、FPGA転送帯域、各処理時間
  • 画面を埋める面積の違いによるラスタライズ負荷も比較

注意：外付けFPGAの方が必ず高速になるとは断定しない。同一解像度、同一シーン、同一描画機能で実測比較する。

非目標（初期段階）

  • OpenGL互換GPUの実装
  • 1280×720 RGB565全面転送で60FPS（8bit PARLIOでは帯域不足）
  • Linuxドライバを前提とすること
  • Linux外部メモリ管理との同時稼働

移植性

GPUの描画RTLとコマンド体系はFPGAボード固有のI/O層・DDRメモリ層から分離し、将来Tang Nano 9K/20K等へ移植可能な構造を目指す。ただしFPGA資源、RAM容量・規格、映像出力はボードごとに異なる。
