GPU LAB 整数CPUバックエンド

2026-10-23。CpuIntegerをBackend契約へ追加した。Mode::CPUのまま、利用するラスタ規則を従来floatと区別する。対応はWire/Polygonのみ。他シーンはavailable=false、render=false。既存Cpuの描画処理は維持する。

数値と処理分担

現在のキューブシーンの頂点回転・投影はCPUのfloat。画面X/Yはfloor(projected*16)でraw signed12.4へ量子化し、範囲-32768..32767を検査する。深度はfloor(50000/camera_depth)、uint16、値が大きい方を近くとする。clamp/wrapは行わない。三角形は整数edge、画素中心、top-left、整数floor深度補間、strict greater Z。線はfloorで整数画素化した端点順Bresenham、色のみ更新する。

固定キューブのcamera depthは4-sqrt(3)以上なのでnear planeを横切らない。このバックエンドは一般メッシュ用のnear clipを実装したものではない。将来の任意メッシュはCPU同次clip規則とnear値を別途固定してから投入する。異常な非有限/範囲外の生成頂点はfalseとし、そのフレームは使用しない（途中まで描いたフレームのrollbackはしない）。

integer_raster::FrameViewは呼出し側のTarget color/depthを直接更新する。全画面の中間vector生成・コピーを行わず、coverage収集も無効にする。Wireはdepthをclear/更新しない。Polygonはdepth=0で初期化する。所有型Frameは従来のdifferentialテスト用APIを維持し、同じViewへ委譲する。

ホスト例外有効時は不正ラスタ命令をinvalid_argumentで拒否する。例外無効の組込みビルドは内部契約違反でabortするため、公開render入口と生成頂点の検査後にのみViewへ渡す。これはUSB等の未検証入力をViewへ直接渡すAPIではない。

比較条件と検証

従来float描画との画像一致は要件ではない。従来は境界全包含、整数版はtop-leftであり、頂点/深度の量子化も異なる。FPGAとの適合・速度比較には同じ整数頂点と規則を使い、CPU geometryの時間も区別して保存する。今回の追加でTab5実測やGPU高速化を確認したわけではない。


python -m unittest discover -s tests -p test_integer_backend.py

python -m unittest discover -s tests -p test_cpp_raster.py

既存compilerのみ利用する。バックエンドの対応範囲、6条件、複数frameと再現性、guard領域、深度、拒否、View/所有型の一致をホストで検証する。従来画像のhashも出力できる。USB/COM、書込み、機器操作は実施しない。

2026-10-23に既存Zig C++で新規バックエンド1テストと既存Python/C++ differential 3テストが成功した。例外無効(-fno-exceptions)のホストコンパイルも成功。ホスト上の従来LIGHT/frame0 checksumはWire=1f647413、Polygon=60bc247e（ホストのfloat演算環境に依存し、Tab5の固定期待値ではない）。ESP-IDF全体ビルドとUI/APIの識別は統合作業で別途確認する。

統合後にESP-IDF全体ビルドが成功。UI/APIのraster識別、整数6条件suite、規則別結果保存を追加した。機器不要のクライアント検証は実施したが、実機のタッチ・USB・表示は未検証。統合記録を参照。
