G0 exact depth RTL 部品（2026-10-23）

rtl/game/triangle_depth.v はcoverage後段の、正確な整数深度補間と

strict-greater深度比較を行うRTLソース。**RTLコンパイル/シミュレーション、合成、

配置配線、資源量、クロック成立、FPGA/Tab5実機動作は未検証**。

新しいシミュレータは導入していない。

入出力と検証契約

  • area、weight_a/b/c: signed64bit。coverage部品が出す元の入力頂点順。
  • za/zb/zc/old_depth: unsigned16bit。larger=near、0=far。
  • covered: この候補画素が幾何的にcoveredかを表す。
  • 正常形状: 0 < area <= 2*65535^2、全weight>=0、weight合計=area。
  • 不正area、負のweight、weight合計の不一致、幾何上限超過は、

invalid_input=1, depth_pass=0, new_depth=0で結果を返す。除算しない。

  • 形状検査はcovered=0でも実施する。正常形状でcovered=0は

invalid_input=0, depth_pass=0, new_depth=0を返し除算しない。

  • covered=1の正常形状は

new_depth=floor((wa*za+wb*zb+wc*zc)/area)、depth_pass=(new_depth>old_depth)。

深度等値はfalse。結果が0でold_depth=0でもfalse。

画素coverage外の重みは負になりうるので、coverage出力から接続する実ラスタライザは

covered=0の候補をこの部品へ送らずスキップするのが基本。

この部品は不正データを描画可能な値にclamp/wrapしない。

framebuffer読出し・更新、color、DDR、エラー通知先、scissor/走査は別部品。

valid/ready・遅延・リセット

入力は立上りのin_valid && in_readyで一度だけ受理する。入力readyが0の間の

入力変更やin_validは無視する。accepted transactionは最大1個。

正常covered入力を受理した立上りの49クロック後にout_validと結果を登録する。

不正入力または正常uncovered入力は、受理した立上り後に結果を登録する。

除算busy中と未消費のout_valid中はin_ready=0。

out_valid && out_readyの立上りで結果を消費する。

out_ready=0の間、out_valid・invalid_input・depth_pass・new_depthは保持する。

結果消費と次入力の同一クロック受理はしない。消費後にin_readyが1へ戻る。

reset_n=0は非同期にbusy/valid/出力/内部状態を0にし、in_readyも0にする。

処理途中や出力待機中のリセットはtransactionを破棄する。

リセット解除後に古い結果を再通知しない。

幅と正確な除算

幾何上限を保守的にMAX_AREA=2*65535^2=8589672450 < 2^33とする。

入力weightは64bitで受け、符号と66bit合計で検査した後、乗算用に33bitを用いる。

33bit weight × 16bit Zは49bit。3項は51bitで足し、正常入力では

sum(weight*Z) <= area*65535 < 2^49なので49bitへの取込みで損失しない。

49bit numeratorを上位bitから1bitずつ処理するrestoring division。

各stepでremainderを左シフトして次bitを加え、divisor以上なら引き、quotientに1を追加する。

divisorは33bit、シフト直後remainderは34bitで比較/減算、終了時remainder<divisor。

正しい入力では商は0..65535。49step終了時の商をuint16として返す。

浮動小数点、reciprocal近似、丸めの置換を使わない。

coverageとの接続範囲

今回、既存triangle_coverage.vは変更していない。coverageはバックプレッシャーなしの登録部品、

depthは単一transactionの逐次部品なので、両者を無条件に直結してはいけない。

呼出し元に「coverageのvalid結果とそのZ/old_depthを保持するレジスタ」、

「covered=0はスキップ」、「depth.in_readyまで保持」、

「out_readyでdepth結果を受取ってから次候補へ進む」制御が必要。

ストール制御とmetadata保持は候補画素wrapperへ実装した。framebuffer更新とDDR接続は未実装。
